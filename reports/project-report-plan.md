## 1. What the report is

One document, built by committed code from recorded runs, in which every number carries the record file and the command that reproduce it, so that the owner can check any number against its record and a reader of the talk sees results and no method. It has three faces, filled from the same records:

- the README sections of each package (schwingcheck/README.md's build-up, chain, one-vertebra, fixed-k and census sections; the morphometrics package's README once pull request 30 lands), whose tables the tests hold to the records;
- the private claude.ai pages the owner reads (reports/every-measure/, this thread's page; the morphometrics thread's status page; a status page per thread as the work grows), each built from the records by a script beside it, its figures the records' own PNGs;
- the talk's figures (CNS, 2 November 2026, mini-oral 66629), chosen from the pages, results only.

Synthetic and real results are never pooled and are always labelled: a number drawn from a published table's generator says so, a number measured on a CT says which tier and which arm (SPINEPS masks, or the second arm of released masks, never pooled with the first).

## 3. The engine as a library

The owner's measure for it is "a high quality version of ostk", the toolkit he named; the qualities taken here are the ones a library is judged by, and the morphometrics thread confirms the name with him. The engine is one installable package with a stable, documented and tested interface, which the naming rule, the census, the pages and later a C-arm reader all call and none of them re-implement:

- **One definition per measure, as data.** A registry of measure specifications, one entry per vocabulary key: kind and units; the landmarks as named points in the vertebra's own frame (as autoanatomist/specs.py names them, "endplate.right", "endplate.left", ...); the plane and axis; the technique that finds each point on a mask and, where one exists, on an image; the papers that define it, with their own words, which research_notes/paper-tables/data/series.csv already carries row by row in its definition column; Panjabi's mnemonic where he printed it; the error bound the census reads (0.75 mm, 4 per cent of an area, 1.5 degrees, 0.04 for a ratio, the morphometrics thread's phantom bounds, or the rule's stated 1 mm, sqrt(pi A / 2) and 3 degrees where the table has no measured error); and its benchmark status. Variants that papers measure differently are distinct keys, as the vocabulary already keeps them (pedicle_w, pedicle_w_inner, pedicle_w_outer), never averaged into one.
- **The expert technique, kept and shown.** For every measure the registry says how it is taken, and the renderer draws the measurement's line on the mask or the CT with the witness voxels beside it (autoanatomist/render.py does this for the oracle's measures today), so the "how to measure" is code that draws what it did, not prose alone. Where the reread's papers describe a technique the engine does not implement, the registry says so, and the measure is ranked by the census from the paper's table but not measured by the engine.
- **A pure function from a labelled volume to readings.** `read(labels, affine, names)` and nothing else: no global state, no file written, the same answer on the same input to the bit (the oracle protocol of autoanatomist/oracle.py), with the vertebral frame built the same way for every measure, so that two measures of one vertebra share one frame.
- **Benchmarked, tested, implemented.** Three benches that every release of the engine passes: phantoms with exact truth (autoanatomist/phantom.py and morphometry/tests/phantom.py), which give each measure its error bound and its invariance to rotation, translation and resampling; the published tables (the census's sources), which say whether the engine's population means and spreads fall where the papers' do, measure by measure and level by level; and the gold tier 3 table against the second arm's masks, never pooled. The bench reports are records, and the README's tables are held to them by tests, as schwingcheck's are.
- **Packaging.** A pyproject with pinned versions (the owner allowed PyMC's packages, pymc-extras' eight and matplotlib; anything else is an issue first), a version number raised by the pull request that changes the interface, a CHANGELOG, and docstrings for a reference page; the standard library and NumPy are enough for the 3D engine itself.
- **The 2D engine reuses the registry.** Each specification carries its projection: which points survive into an AP or a lateral view and how (an end-plate width survives into AP as the plate's silhouette, an inclination into lateral, a canal area into neither). The 2D reader finds the projected landmarks on an image and calls the same `Spec.value`; the DRR route supplies the truth.

## 5. The standards every section keeps

- Figures: anatomy in Benzel's style; line graphs in the house format of schwingcheck/figures.py (ink, serif, lettered panels, one line and marker per series); drawn by committed code from recorded inputs, each with its CSV and caption beside it and FIGURES.md naming record and code by sha256.
- Numbers: every share with its interval or Monte Carlo error; every count said as what it is made of; synthetic and real never pooled; the levels' truth only from spines countable from C2.
- Records: a record names the commit that made it and that the package did not change while it ran; the tests hold the README to the record and the figures to the code.
- Confidentiality: bordercall and SchwingNet's research notes stay in their repositories; the talk shows results, not methods.
